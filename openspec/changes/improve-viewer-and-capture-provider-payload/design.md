# Design

## Context

- 查看页面是 `src/records/viewer/page.ts` 里的单块内联 HTML，详情渲染在列表下方，`JSON.stringify` 出来的快照没有格式化和换行开关。
- 记录存储 `MaskingRecordStore` 把整条 `MaskingRecord` 序列化进 `payload`，索引列表只取摘要列，因此新增字段不需要迁移表结构。
- 宿主在一次模型请求前依次触发 `context_with_system`、`before_provider_headers`、`before_provider_request`；后者拿到供应商序列化后的请求体。

## Goals / Non-Goals

**Goals:**

- 让页面在打开后立即看到第一条记录的内容，详情可读、可搜索、可复制。
- 让用户能对照"扩展收到的上下文 / 扩展输出的上下文"和"发送前钩子看到的请求体"。

**Non-Goals:**

- 不抓包、不改传输层，不声称与最终网络字节一致。
- 不采集请求头、认证信息或模型响应。
- 不引入前端框架、构建步骤或外部静态资源。

## Decisions

### 详情改为列表 + 详情双栏，默认选中首条

文档化的"点行滚到页尾看详情"在长列表中不稳定。改为固定详情区并默认选中首条记录后，打开页面即能看到内容；窄屏回落为上下排列。

### 供应商请求作为独立来源记录，不做时间关联

`before_provider_request` 的载荷与某条 `context_with_system` 记录之间没有可靠标识可关联；按时间邻近推断会在重试、多扩展改写时给出错误结论。因此单独记录来源 `provider_request`、范围 `provider-payload`，页面明确标注采集阶段。

备选：把请求体塞进上下文记录。否决原因：一次上下文事件可能对应多次供应商请求（重试），一对多塞进同一条会丢信息或误导。

### 请求体只观察，不替换载荷

钩子返回 `undefined` 保持载荷不变，与现有"记录不影响脱敏主流程"的约束一致。排在 Rehydra 之后的扩展仍可能改写载荷，页面必须写明这一点。

### 二进制与超限沿用快照规则

复用 `serializeSnapshot` 的二进制省略与 `maxRecordBytes` 预算；补充供应商常见图片形态（`type: "base64"` 的 `data`、`data:` URL）只留标记。超限时截断并标记，不伪称完整。

### 关闭原文保存时不采集请求体

请求体就是原文，`includeOriginal: false` 时没有可脱敏后的替代内容，因此不落盘正文；页面不显示这类记录，也不回填上下文冒充请求体。

## Risks / Trade-offs

- [请求体可能含敏感数据] → 受 `record.enabled` / `includeOriginal` 控制，沿用 0700/0600 权限与保留裁剪；页面标注仅本机、明文保存。
- [请求体体积大] → 复用单条字节预算截断并显式标记；关闭原文保存即可完全停止采集。
- [钩子未触发或驱动不同传输] → 页面显示"未采集"的事实，不推断；旧记录不补造。
- [同步写 SQLite 增加请求延迟] → 单次写入与现有记录路径相同，失败只告警不阻断。

## Migration Plan

无数据迁移。新增字段为可选，旧记录照常读取；回滚只需还原扩展代码与页面。
