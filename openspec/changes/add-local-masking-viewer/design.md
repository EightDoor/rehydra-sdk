# Design

## Context

- 现有脱敏记录（`src/records/recorder.ts`）按天写 JSONL，只保存"字段级变化"对照，`/rehydra log` 是唯一查看入口。
- 用户要核对的是"模型到底看到了什么"：需要扩展收到的完整内容与扩展输出的完整内容并排对照，包含未命中字段。
- Pi 扩展最低运行时是 Node.js 22.19（`packages/pi-extension/package.json`），`node:sqlite` 自 22.5 起可用。
- SDK 的浏览器入口（`src/browser.ts`）不能引入 Node 内置模块；查看服务只在 Pi 扩展路径使用。

## Goals / Non-Goals

**Goals:**

- 记录改为 SQLite：可索引、可分页筛选、可按会话清理。
- 每条记录保存完整文本快照（钩子收到的内容 / 扩展输出的内容）。
- 启动即可访问的本机网页，展示快照、命中明细与状态。
- 移除命令行入口，查看与清理统一在网页完成。

**Non-Goals:**

- 不做局域网访问、登录态或 HTTPS。
- 不迁移、不导入、不删除旧的 JSONL 记录文件。
- 不改变脱敏策略本身：识别规则、失败放行、工具阻断语义保持原样。
- 不做供应商实际报文的抓包比对。

## Decisions

### 记录存储用 `node:sqlite`，不引入 better-sqlite3

Pi 扩展运行时已有 Node.js 22.19，`node:sqlite` 够用；`better-sqlite3` 是原生模块，会给安装用户带来编译负担。

备选：复用 `src/storage/sqlite.ts` 的 `SQLitePIIStorageProvider`。否决原因：那是加密 PII 映射存储，语义、清理策略与访问模式都不同，混在一起会让"还原映射"和"审计记录"互相牵连。

### 完整快照与字段级对照并存

快照按整条消息树序列化，保留角色、块顺序与工具参数结构；字段级对照继续保留，用于定位具体变化的字段路径。

备选：只用字段级对照。否决原因：用户要看的正是"没被改动的部分也在"这件事，字段级对照看不到。

备选：只保留快照、删除对照。否决原因：字段路径信息会丢失，误遮蔽定位变难；且快照已覆盖对照的内容，删掉对照反而丢信息。

### 快照按字节截断，截断即声明

快照两侧共用 `maxRecordBytes` 预算，超出各自截断并置 `truncated`，页面明确提示不完整。

备选：静默截断。否决原因：页面会把不完整内容当成完整内容展示，核对结论会出错。

### 记录默认开启且默认保存原文

用户明确要求"启动即可看到"。代价是原文明文落盘，因此配套：目录 0700、库文件 0600、`secure_delete`、按天与总量裁剪、页面提供二次确认的清理入口。

### 网页只监听 127.0.0.1，用浏览器同源约束代替登录

无凭证的本机页面，任何本机进程都能读到记录原文；这是用户确认的取舍。访问控制因此放在浏览器侧：校验 `Host`（挡 DNS 重绑定）、校验 `Origin`、拒绝 `Sec-Fetch-Site: cross-site`、拒绝 CORS 预检、数据接口要求自定义请求头（跨站表单与 `<img>` 无法携带）。

备选：加登录口令。否决原因：用户明确要求不带访问凭证。

备选：只监听 127.0.0.1 就够了。否决原因：本机任意网页仍可发跨站请求读取记录内容（配合 DNS 重绑定可打到 localhost），只靠监听地址挡不住。

### 快照只在"保存原文"开启时落盘

`includeOriginal: false` 时不保存任何前后文本，只留命中类型、检测器、占位符、长度与偏移。

### 命令行入口整体移除

`/rehydra` 的状态、查看、清理全部由网页承接。保留命令等于两套查看路径，后续必然漂移。

### 旧 JSONL 文件不迁移

新记录只写 SQLite；旧文件保持原样，也不在新页面展示。用户可自行删除。

## Risks / Trade-offs

- [原文默认明文落盘且页面无认证] → 目录/文件权限收紧、裁剪策略、页面明确标注"仅本机"、文档单列风险说明；用户可用 `record.enabled: false` 或 `includeOriginal: false` 关闭。
- [`node:sqlite` 在 Node 22/24 仍是实验特性] → 加载时临时吞掉那条实验警告；驱动不可用时告警并放弃持久化，不影响脱敏主流程。
- [快照体积大] → 单条 4 MiB、总量 32 MiB、7 天上限，写入时裁剪；超限截断并显式标注。
- [SQLite 写入是同步的] → 单条写入在脱敏路径上会产生微小延迟；WAL + 250ms 锁等待上限避免长阻塞。
- [多进程同时写同一库] → 记录标识带进程号避免主键冲突；WAL 支持并发读者。

## Migration Plan

无数据迁移。回滚只需还原扩展代码；SQLite 库文件保留在原目录即可。
